What agent-md-specs Defines

The project extends the Markdown pattern used by AGENTS.md, CLAUDE.md, SKILL.md, and other agent configuration files into governance and accountability dimensions.

Identity and authorization

Specs such as WHOAMI.md, ID.md, DELEGATION.md, and PERMISSIONS.md describe who an agent is, who authorized it, and what it may access.

Safety and accountability

Specs such as LIMITS.md, ESCALATION.md, AUDITTRAIL.md, and ENFORCEMENT.md document boundaries, human review, evidence, and verification.

Runtime-ready structure

YAML frontmatter and JSON Schemas let policy engines, CI checks, API gateways, and orchestration systems parse the same files humans review.

Who It Is For

agent-md-specs is for AI agent builders, security architects, compliance teams, platform engineers, and open-source maintainers who need a plain-language Markdown vocabulary for agent behavior and governance.

Use case Start with Purpose
Basic agent documentation SOUL.md, WHOAMI.md, LIMITS.md Explain identity, personality, and hard operating boundaries.
Enterprise governance DELEGATION.md, CONSENT.md, LEASTPRIVILEGE.md Map human authority, user consent, and zero-trust access controls.
Audit and incident review AUDITTRAIL.md, PROVENANCE.md, CIRCUITBREAKER.md Record what happened, where data came from, and how failures are contained.
